The first alpha, and the parts we could not run

2026-09-09 · candidate 0.1.0a1

Ackline release history. The project is now Zab-al-ack; this post retains the names and results recorded for this candidate.

Ackline 0.1.0a1 is the first candidate we were willing to hand to a reviewer. It contains the whole thing: the Alerta plugins, the PostgreSQL capture and ledger, the worker, the reconciler, the CLI, the labs, the deployment tooling, the docs and the licences.

What it does is deliberately small. One authorised human acknowledges one Alerta alert. The database captures a signed intent in the same transaction. A worker verifies it, checks the original Zabbix problem, and delivers a bounded acknowledgement. Uncertain outcomes are investigated without blindly repeating a write. Bulk actions and chatops remain outside the alpha scope.

What we could run: the unit and mocked suites and the SQL groups on PostgreSQL 18 compiled to WASM. What we could not run in that workspace: native PostgreSQL with PgBouncer, and a real Zabbix. The report says NOT_RUN where that is true. We would rather ship a smaller claim than a bigger one we cannot back.

Three dependency advisories turned up during preparation. We bumped the pins, recorded why, and kept the pre-fix scan next to the final one. Python support is what we tested: 3.12.

Details for this candidate are in the cumulative changelog and the release amendments shipped with the source. Nothing on this page is a production or publication claim.
