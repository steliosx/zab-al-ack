Generated tests find a dead end

2026-09-11 · candidate 0.1.0a6

Ackline release history. The project is now Zab-al-ack; this post retains the names and results recorded for this candidate.

a6 is the candidate where the tooling caught up with the ambition. Ruff and a gradual strict mypy over the sensitive modules. Hypothesis exploring the trust boundaries and driving generated sequences through the restricted ledger functions. Native tests that spawn competing worker processes, drop responses, kill a worker after the remote commit, and check that nobody sends twice.

The generated sequences found a real dead end. An operator confirms that an uncertain attempt had no effect before its deadline. The action becomes failed, which is right. But expiry cleanup then left its source-effect generation open, and a later human action could stay coalesced behind that old generation forever.

The fix is forward migration 007: the expiry helper now also closes confirmed no-effect work at its original deadline. Nothing is retried automatically; nothing is written to Zabbix. Schema version 3.

Evidence became execution-owned in this release too: recorders run the tests they record and invalidate prior success before doing anything else. What a6 did not have was a machine that could run its own native and service suites. It said so.

Details for this candidate are in the cumulative changelog and the release amendments shipped with the source. Nothing on this page is a production or publication claim.
