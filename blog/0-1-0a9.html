Meet Zab-al-ack

2026-09-12 · candidate 0.1.0a9

Our new name puts the integration in the name: Zabbix, Alerta and acknowledgements. Say “Zabalack.” Write Zab-al-ack for the project, and zabalack in a terminal or Python import.

The purpose stays the same. An authorised person acknowledges an eligible Alerta alert; the integration captures a signed request, checks the original Zabbix problem and delivers a bounded acknowledgement. It keeps a record of the outcome and investigates uncertainty without blindly repeating a write.

More than the wordmark

a9 renames the Python package, CLI, Alerta plugin entry points, configuration keys, database schema and roles, services, media artifact, monitoring labels and development tooling. The familiar Alerta-inspired mark stays, with the new name across the homepage, docs and blog.

Old evidence keeps its identity

Database names and signed markers are part of a delivery contract. a9 therefore uses a fresh zabalack installation namespace and refuses a database containing Ackline. It does not provide an in-place upgrade. Keep existing Ackline installations on their reviewed release until an appropriate transition is approved; retain their ledger, history and original migration checksums.

The new HMAC domain rejects old proofs, including one with only its visible prefix relabelled. Both proof formats still receive log redaction. The webhook suppresses either exact neutral comment format before accessing an endpoint or credential. Recognising an echo grants no permission to acknowledge an event.

Checked on the renamed source

The a9 reference run passed 796 tests, failed none and explicitly skipped 22: 768 unit, mocked, property and offline checks, and 28 PostgreSQL WASM passes. Fifteen new regression cases cover the namespace boundary, privacy and installation guards. The synthetic webhook suite now has 15 groups.

The eight engineering upgrades and the a8 review’s strict evidence validator remain in place. Fresh run records bind to the a9 source and harness; historical Ackline results are kept separately. Native database authentication and concurrency, PgBouncer, real Zabbix and the complete installed-wheel service path require fresh execution on a supported host. G1–G8 remain deployment gates.

Start with the transition guidance, or follow the isolated quickstart for a new evaluation. The source handoff includes the full changelog, rename rationale, SQL hash comparison, deployment inputs and rollback instructions.

Zab-al-ack is independent of Alerta and Zabbix. Public package and repository ownership are still being prepared. The website is informational and does not connect to monitoring systems.
