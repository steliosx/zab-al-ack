The evidence file nobody else could read

2026-09-13 · candidate 0.1.0a15

a14 brought contributor guidance, three repository skills and retained review runs, and said plainly that it could not run the database, Zabbix or installed-wheel service layers. a15 ran them. It also found an evidence-writer defect inherited from a7.

A mode, not a mistake in logic

The mutation runner writes its evidence the careful way: to a temporary file, then an atomic rename. mkstemp creates that temporary file with mode 0600, and os.replace keeps whatever mode it finds. So the published record — a file meant to be read by anyone verifying the release — arrived owner-only, while every other record beside it was 0644.

Nothing failed. The tests passed, the audit passed, the checksums matched. The consequence appears when someone other than the producer reads the records: on the working tree as another account, or from an archive that preserved the mode. We confirmed it the blunt way, by having an unprivileged account read the evidence directory: quality-run.json fine, mutation-pr-run.json permission denied. The delivered a13 archive carries the same 0600 inside it.

This is ours, not a14’s. It dates from a7, when the mutation runner was added. a14 inherited it and, by splitting the record into per-profile files, turned one unreadable file into three. Corrected in a16: the original version of this post said the mode had shipped in every handoff since a7. The writer was wrong throughout, but only some handoffs carried it to a reader — a10, a12 and a13 did; a14 and a15 stored those records 0644. The full correction →

Fixing the class, not the instance

Each writer now names the mode it means: 0644 for published evidence, 0600 for the private diagnostic copy that stays inside its own 0700 directory. That alone would fix today’s three files and leave tomorrow’s writer free to repeat the mistake, so the export audit now checks every exported file and reports any that is not readable to group and other. Two regressions pin both halves.

And the suites a14 could not run

Forty-two native PostgreSQL 18.3 and PgBouncer cases across five fresh clusters, six real Zabbix 7.0.10 contract cases including the excluded-action denial, and the deployment lab’s four tests with all thirteen observations from the installed a15 wheel. Those runs belong to a15; a14 changed no service-path file, which is grounds for an inference about its code, not a substitute for its own records. Everything a14 reported offline reproduced here exactly.

Still open, unchanged: the webhook transport limitation A2, the Docker Compose forms, hosted CI, signed attestation, and the eight deployment gates.
