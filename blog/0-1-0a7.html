Mutants, a deployment lab, and honest NOT_RUNs

2026-09-11 · candidate 0.1.0a7

Ackline release history. The project is now Zab-al-ack; this post retains the names and results recorded for this candidate.

Do the tests notice when the code gets worse? a7 answers with a reviewed mutation catalogue: twelve substitutions for every pull request, twenty nightly, each one removing a guard around authority, binding, identity or writes. A surviving mutant fails the gate. The first expanded run left one alive, a wrong-event check with no negative test. Two regressions later it did not.

The bigger addition is a deployment-path lab that uses the software the way an operator would: the installed Alerta app factory behind a real HTTPS process, ordinary signup and login, the installed worker CLI as its own process, separate password-authenticated database roles, a real Zabbix with media import, macros, update notifications and recovery.

And here is the honest part. The workspace that prepared a7 had no Docker and no supported native runtime. Native PostgreSQL, real Zabbix and that new lab were all NOT_RUN, and every document said so instead of pointing at an older run.

Source inspection also recorded amendment A2: the Zabbix webhook client does not verify TLS peers and follows redirects. An HTTPS URL alone proves nothing about ingestion. That stays a deployment gate.

Details for this candidate are in the cumulative changelog and the release amendments shipped with the source. Nothing on this page is a production or publication claim.
