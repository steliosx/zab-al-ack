A reviewer ran it on a real database. It failed.

2026-09-10 · candidate 0.1.0a2

Ackline release history. The project is now Zab-al-ack; this post retains the names and results recorded for this candidate.

The first independent review did what we could not: it built PostgreSQL 18.3 and PgBouncer from source and ran the native phases. Two of the four failed. Two tests had hard-coded the worker's expected database name as postgres; the lab database is called alerta. The worker's health check said no, correctly, and the tests blamed the worker.

The fixture now reports the database it is actually connected to, and the tests use that. A second bug hid behind the first: a checkout path longer than about ninety characters made the lab's Unix socket path too long to start a cluster.

Two SQL corrections came out of reading the design baseline against the migrations. The worker role had an EXECUTE grant it never used and should not have had. And when a marker failed to parse, the capture stored up to 256 characters of whatever followed it, which could be an operator's free-text note. Now it stores nothing.

Evidence hygiene changed too: timestamps in UTC, no host fingerprints in the reports, and the acceptance matrix shows native PASS only where a native check ran. Twenty native cases, zero failures.

Details for this candidate are in the cumulative changelog and the release amendments shipped with the source. Nothing on this page is a production or publication claim.
