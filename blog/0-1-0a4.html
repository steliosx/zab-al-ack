A late response should not clear an unresolved send

2026-09-10 · candidate 0.1.0a4

Ackline release history. The project is now Zab-al-ack; this post retains the names and results recorded for this candidate.

The independent review of a3 found something the suites had not: when a Zabbix response arrived after the delivery lease had expired, the ledger recorded it as late but left the action eligible for another send. A replacement worker could also clear uncertainty it had inherited. That is exactly the class of bug this project exists to prevent: a second acknowledgement nobody asked for.

The reviewer wrote a seven-scenario SQL group that fails on a3 and passes with the fix, and shipped the fix as forward migration 006 with a data repair, a schema-version gate and an explicit reseal step. We could have folded it into the earlier migration; no a3 installation exists. We kept 006 as built, because the upgrade path is the thing a beta has to be able to walk.

We ran it natively, including both 005→006 upgrade scenarios, and then added the case we had been missing: a real Alerta HTTP acknowledgement, captured by the trigger, verified and delivered by the production worker to a real Zabbix, read back from the ledger, the projection and Zabbix itself. One write. A second pass writes nothing.

Details for this candidate are in the cumulative changelog and the release amendments shipped with the source. Nothing on this page is a production or publication claim.
