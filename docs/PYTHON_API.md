# Shared package interfaces

`config.Settings` / `load_settings(path)` provide strict JSON configuration. The production example is inert. Secrets use absolute protected files; the configuration checker reads metadata and never resolves endpoint credentials. `read_protected_file()` disallows symlinks, nonregular files and group/world access.

`crypto.build_intent(alert_id, customer, source, actor, cohort_revision, policy_revision, now=None, action_id=None)` returns the strict v1 binding. Source keys are zabbix_instance/zabbix_event_id/zabbix_trigger_id. Actor keys are login, customers (sorted unique), admin, auth_type (`user`). Top-level keys are version/action_id/alert_id/customer/source/actor/route/action/cohort_revision/policy_revision/issued_at/capture_expires_at/execution_expires_at. The route is the canonical full alert ID route; the actual request context must independently qualify. Timestamps are UTC ISO-8601 strings, capture 60 seconds, execution four hours.

`canonical_bytes` uses UTF-8 (no Unicode normalization), JSON sorted object keys, compact separators, no nonfinite numbers, and the prefix `zabalack\x00v1\x00`. Schema contains no floating-point data. Maximum intent 16,384 bytes, marker 256 bytes, history text 65,536 bytes, signer note 8,192 bytes. Reserved marker syntax is accepted only once, as an exact suffix. HMAC-SHA256 MAC is lowercase hex. Key IDs use 1–32 ASCII alphanumeric/dot/underscore/dash characters. Keys are 32–128 bytes. No keys reside in SQL.

`verify_capture(capture, keys, now=None)` verifies schema/MAC/exact frozen snapshot/history actor/capture time before returning intent. Captures supply intent, marker, alert_id, customer, source, history_type, history_user, resulting_status and captured_at. `BindingError` is terminal; `KeyUnavailable` holds for a verifier incident. Processing delay beyond 60 seconds is allowed when database capture was timely. Delivery checks execution expiry independently and read-only reconciliation remains possible after expiry.

`policy.validate_source` preserves unrelated attributes and enforces the seven source fields, IDs and separate recovery identity. `make_snapshot` returns only the three source selectors. `select_cohort(settings, customer, source)` is a pure lookup. `authorize_actor` checks human authenticated scope, with explicit cohort administrative exception. The plugin checks the approved administrative identity exception too. `authorize_intent` rechecks current cohort revision/one-to-one/actor authority. SQL must recheck the same controlled policy before claims/writes.
